# Restartable worker host

The worker host reads and writes the length-prefixed, versioned protobuf frames
defined by `job_service`. It is a restartable process boundary for expensive
media work. Encoded media is written to local files; raw video and audio frames
never cross protobuf or UI boundaries.

## Proxy job contract (v1)

Set `JobSpec.kind` to `JOB_KIND_PROXY` and provide:

| Field | v1 requirement |
| --- | --- |
| `job_id` | Canonical UUID job identifier generated by `job_service`. |
| `project_revision` | Accepted for attribution; proxy generation does not interpret it. |
| `project_checkpoint` | Empty. |
| `input_uris` | Exactly one absolute, UTF-8 local filesystem path to a regular source file. Despite the historical field name, URLs are not accepted. |
| `output_uri` | An absolute, UTF-8 local filesystem path for the proxy. The service writes atomically. |
| `preset_id` | `video-editor.proxy.prores-half.v1` or `video-editor.proxy.ffv1-half.v1`. |
| `options` | Empty. Unknown future options fail closed. |

The ProRes preset requests half-resolution ProRes Proxy/MOV with 48 kHz PCM and
allows the proxy service's deterministic FFV1/Matroska fallback. The FFV1
preset requires half-resolution FFV1/Matroska with 48 kHz PCM and does not
fall back to another video codec. Both profiles retain the service's 1920x1080
maximum. The exact source-PTS map is written to `<output_uri>.vepts`.

Events are emitted in this order: `ACCEPTED`, zero or more monotonic `RUNNING`
updates, then exactly one `SUCCEEDED`, `FAILED`, or `CANCELLED` terminal event.
A success uses `result_uri` for the proxy and reports the map path, resolved
codec/container, fallback decision, dimensions, and frame/sample counts in
metadata. Worker and protocol versions are attached to every event.

## Transcription job contract (v2)

Set `JobSpec.kind` to `JOB_KIND_TRANSCRIBE`, use preset
`video-editor.transcribe.whisper-base.v1`, provide exactly one absolute UTF-8 local input path, and
leave output/checkpoint fields empty. `options` is a typed `TranscribeOptions` message; malformed,
unknown-field, unsupported model/language/range, or future-schema values fail before media I/O.
The stable preset name remains v1; the independently versioned typed options/result payload is v2.

The worker verifies the already-installed pinned model, seeks and decodes only the requested
authoritative source range to mono float32 at 16 kHz, invokes the optional whisper.cpp backend, and
returns a typed `TranscriptionResult` with source-absolute word timing, probability, language,
backend, model digest, and truthful compiled Vulkan capability. Both source-range fields set to zero
mean the complete input; otherwise the duration must be positive. It never downloads a model and
raw audio never crosses the protocol. A build without the optional backend returns
`backend-unavailable`.

The desktop uses one fresh host process per transcription request. Closing that process is its
cancellation/crash-containment boundary; project state changes only after the desktop validates and
reviews the terminal result.

## Proxy cancellation limitation

The protobuf protocol contains `CancelJob`, but the current stdin/stdout host
dispatches one job synchronously. It cannot read another frame while FFmpeg is
running, so it cannot receive an in-flight cancellation request. A cancellation
request that reaches the idle loop returns an explicit
`unsupported-cancellation` failure. The worker does not claim cancellation
occurred. Proxy generation still uses its real stop-token path if the event
sink fails (for example, when the parent pipe closes), preserving atomic output
safety. Concurrent cancellation requires a future duplex reader/dispatcher or
the planned named-pipe/Unix-socket job service.

## Current coverage

`JOB_KIND_PROBE`, `JOB_KIND_PROXY`, and `JOB_KIND_TRANSCRIBE` are implemented. Thumbnail, waveform,
render-cache, and export jobs return an `unsupported-job` failure.
