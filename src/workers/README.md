# Restartable worker host

The worker host reads and writes the length-prefixed, versioned protobuf frames
defined by `job_service`. It is a restartable process boundary for expensive
media work. Encoded media is written to local files; raw video and audio frames
never cross protobuf or UI boundaries.

## Proxy job contract (v1)

Set `JobSpec.kind` to `JOB_KIND_PROXY` and provide:

| Field | v1 requirement |
| --- | --- |
| `job_id` | Canonical UUID job identifier generated by `job_service`. |
| `project_revision` | Accepted for attribution; proxy generation does not interpret it. |
| `project_checkpoint` | Empty. |
| `input_uris` | Exactly one absolute, UTF-8 local filesystem path to a regular source file. Despite the historical field name, URLs are not accepted. |
| `output_uri` | An absolute, UTF-8 local filesystem path for the proxy. The service writes atomically. |
| `preset_id` | `video-editor.proxy.prores-half.v1` or `video-editor.proxy.ffv1-half.v1`. |
| `options` | Empty. Unknown future options fail closed. |

The ProRes preset requests half-resolution ProRes Proxy/MOV with 48 kHz PCM and
allows the proxy service's deterministic FFV1/Matroska fallback. The FFV1
preset requires half-resolution FFV1/Matroska with 48 kHz PCM and does not
fall back to another video codec. Both profiles retain the service's 1920x1080
maximum. The exact source-PTS map is written to `<output_uri>.vepts`.

Events are emitted in this order: `ACCEPTED`, zero or more monotonic `RUNNING`
updates, then exactly one `SUCCEEDED`, `FAILED`, or `CANCELLED` terminal event.
A success uses `result_uri` for the proxy and reports the map path, resolved
codec/container, fallback decision, dimensions, and frame/sample counts in
metadata. Worker and protocol versions are attached to every event.

## Transcription job contract (v2)

Set `JobSpec.kind` to `JOB_KIND_TRANSCRIBE`, use preset
`video-editor.transcribe.whisper-base.v1`, provide exactly one absolute UTF-8 local input path, and
leave output/checkpoint fields empty. `options` is a typed `TranscribeOptions` message; malformed,
unknown-field, unsupported model/language/range, or future-schema values fail before media I/O.
The stable preset name remains v1; the independently versioned typed options/result payload is v2.

The worker verifies the already-installed pinned model, seeks and decodes only the requested
authoritative source range to mono float32 at 16 kHz, invokes the optional whisper.cpp backend, and
returns a typed `TranscriptionResult` with source-absolute word timing, probability, language,
backend, model digest, and truthful compiled Vulkan capability. Both source-range fields set to zero
mean the complete input; otherwise the duration must be positive. It never downloads a model and
raw audio never crosses the protocol. A build without the optional backend returns
`backend-unavailable`.

The desktop uses one fresh host process per transcription request. Closing that process is its
cancellation/crash-containment boundary; project state changes only after the desktop validates and
reviews the terminal result.

## Proxy cancellation

The protobuf protocol contains `CancelJob`. The stdin/stdout host keeps a
background reader on stdin while a job runs on a worker thread, so in-flight
`CancelJob` frames reach `CancellationRegistry` and stop proxy/export/transcribe
work through the existing stop-token paths. A cancellation request for an
unknown or idle job returns an explicit `job-not-found` failure. The desktop
sends `CancelJob` over the open stdin channel and falls back to process kill
only when the write fails or no terminal event arrives within a few seconds.
Proxy generation still uses its real stop-token path if the event sink fails
(for example, when stdout closes), preserving atomic output safety. Named-pipe
and Unix-socket routing remain out of scope.

## Export job contract (v1)

Set `JobSpec.kind` to `JOB_KIND_EXPORT` and provide:

| Field | v1 requirement |
| --- | --- |
| `job_id` | Canonical UUID job identifier generated by `job_service`. |
| `project_revision` | Accepted for attribution; the worker deserializes `project_checkpoint`. |
| `project_checkpoint` | Absolute UTF-8 path to a serialized project snapshot written by the desktop. |
| `input_uris` | Empty. Original media paths come from the checkpoint assets. |
| `output_uri` | Absolute UTF-8 destination path. The export service writes atomically. |
| `preset_id` | `video-editor.export.creator.v1`. |
| `options` | Typed `ExportOptions` (`schema_version` 1). Unknown fields fail closed. |

The worker deserializes the checkpoint, snapshots the requested sequence, registers each asset
`source_uri` as an original (never a proxy), builds `FfmpegFrameProvider` + `CpuRenderer` and
`OriginalAudioRegistry` + `TimelineAudioRenderer`, then calls `export_service::export_video`.
Hardware-to-software fallback stays inside that call and is surfaced as a `RUNNING` event with
phase `hardware-fallback`. Success metadata includes `frame_count`, `audio_sample_count`,
`video_encoder`, and `hardware_encoder_used`.

The desktop launches one fresh host process per export, writes the checkpoint to a unique temp
file, and deletes that file when the process finishes. Closing the process is the
cancellation/crash-containment boundary; a killed worker leaves the destination unchanged.

## Thumbnail job contract (v1)

Set `JobSpec.kind` to `JOB_KIND_THUMBNAIL` and provide:

| Field | v1 requirement |
| --- | --- |
| `job_id` | Canonical UUID job identifier generated by `job_service`. |
| `project_revision` | Accepted for attribution; thumbnail generation does not interpret it. |
| `project_checkpoint` | Empty. |
| `input_uris` | Exactly one absolute, UTF-8 local filesystem path to a regular source file. |
| `output_uri` | Absolute UTF-8 path for a temporary JPEG blob written atomically by the worker. |
| `preset_id` | `video-editor.thumbnail.v1`. |
| `options` | Typed `ThumbnailJobOptions` (`schema_version` 1). Unknown fields fail closed. |

The worker decodes one deterministic frame through `media_cache::generate_thumbnail` into a
private staging `CacheStore`, then writes only the JPEG bytes to `output_uri`. Raw frames never
cross the protocol. Success uses `result_uri` and reports `asset_id`, `parameter_hash`, and
dimensions in metadata. The desktop adopts the blob with `CacheStore::put_file` into its own
single-writer store.

## Waveform job contract (v1)

Set `JobSpec.kind` to `JOB_KIND_WAVEFORM` and provide:

| Field | v1 requirement |
| --- | --- |
| `job_id` | Canonical UUID job identifier generated by `job_service`. |
| `project_revision` | Accepted for attribution; waveform generation does not interpret it. |
| `project_checkpoint` | Empty. |
| `input_uris` | Exactly one absolute, UTF-8 local filesystem path to a regular source file. |
| `output_uri` | Absolute UTF-8 path for a temporary `VEWAVE01` blob written atomically by the worker. |
| `preset_id` | `video-editor.waveform.v1`. |
| `options` | Typed `WaveformJobOptions` (`schema_version` 1). Unknown fields fail closed. |

The worker decodes and builds a pyramid through `media_cache::generate_waveform` into a private
staging `CacheStore`, then serializes the waveform to `output_uri`. The desktop adopts the blob
with `put_file`. Cancellation or failure removes the temp output and never commits a partial
index entry in the desktop store.

## Current coverage

`JOB_KIND_PROBE`, `JOB_KIND_PROXY`, `JOB_KIND_TRANSCRIBE`, `JOB_KIND_EXPORT`,
`JOB_KIND_THUMBNAIL`, and `JOB_KIND_WAVEFORM` are implemented. Render-cache jobs return an
`unsupported-job` failure.
